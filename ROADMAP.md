# InvokeSmith public roadmap

InvokeSmith follows evidence gates, not a fixed list of platform compilers.

## Available now

- Versioned TypeScript action contract and deterministic compiler
- MCP target generation and semantic-loss reporting
- Local authoritative outcome tests and adversarial cases
- JSON-file, HTTP, and customer-hook observation providers
- Minimized evidence, Ed25519 signatures, and offline verification
- Policy IR, AuthZEN-compatible reference PDP, and SmithTasks enforcement point
- Declarative release decisions and a reproducible end-to-end demo
- OutcomeGap OG-001 with independently runnable buggy and fixed applications

## Next: prove the wedge with real actions

- Publish the open-source project and qualification questionnaire
- Evaluate qualified consequential actions with design partners
- Prove one real action through a customer-controlled observation provider
- Document whether evidence changed an actual release decision
- Select the first production policy-enforcement integration from partner demand

## Demand-gated branches

These are candidates, not commitments:

- Hosted evidence history and collaborative release approvals
- Managed Linux CI execution with customer-controlled private runners
- Policy lifecycle operations, revocation, replacement, and audit integrations
- A second policy enforcement point to prove portability
- A second action surface only when cross-surface equivalence is buyer-critical
- Enterprise identity, regional execution, retention, and access controls

## Explicitly not promised

InvokeSmith is not currently committing to compile every action into WebMCP, Apple App Intents, Android AppFunctions, Windows App Actions, or A2A. Each additional surface must earn its place through repeated customer evidence and a testable semantic-equivalence requirement.
